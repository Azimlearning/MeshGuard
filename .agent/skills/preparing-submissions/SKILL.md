# Submission Preparation Skill

## When to use this skill
- The user is getting ready to submit their project for a hackathon.
- The user needs to prepare a video presentation script.
- The user needs to verify that the project repo is ready for judges.

## Workflow
- [ ] **1. Source Code Repository Check**:
    - Remind the user to ensure the repository visibility is set to **Public**.
    - Verify that `README.md` is complete, judge-friendly, and has clear setup instructions.
- [ ] **2. Video Presentation Scripting**:
    - Generate a 5-10 minute outline or script covering exactly these points:
        1. Team Introduction
        2. Case Study Selection
        3. The Solution (Value Proposition)
        4. Front-End Demo instructions
        5. Tech Stack & AI Frameworks used
        6. Market Strategy (Business Model, Market Segment, Competitor Analysis)
        7. The Future (Room for improvement, scalability)
- [ ] **3. Video Deliverables Guide**:
    - Remind the user of the final naming convention: `VHACK2026_[TEAM NAME]_[PROJECT TITLE]`
    - Suggest platforms (YouTube Unlisted or Google Drive Public Link) for hosting.
- [ ] **4. Final Review**: Ensure all required materials align with standard hackathon rubrics (Impact, Innovation, Technical Complexity, Presentation).

## Instructions

### Rule 1: Tailor the Script
When generating the video script, ask the user constraints like:
- Who is speaking?
- What are the team members' names?
- What is the chosen Case Study?
- Any specific competitor or market data they have?
Wait for their response before generating the final script.

### Rule 2: README Polish
Offer to review `README.md` using the same criteria judges will use. Look for quick starts, architecture diagrams, and a clear problem statement. If an architecture diagram is missing, offer to create one with mermaid.js.
